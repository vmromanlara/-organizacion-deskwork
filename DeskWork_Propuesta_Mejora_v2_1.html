DeskWork Design System v2.0

Propuesta de mejora manteniendo simplicidad, facilidad de uso e integración

Resumen Ejecutivo

Este documento propone 8 mejoras estratégicas al sistema DeskWork que amplían su capacidad sin sacrificar la elegancia y facilidad de uso que lo define. Cada mejora está pensada para ser incremental, documentada y retrocompatible.

Áreas de mejora:

  1. Tokens CSS + Documentación del Sistema — Estandarización de variables
  2. Componentes Interactivos Completos — Formularios, validación, loading
  3. Sistema de Iconografía Nativo — Conjunto de iconos minimalista
  4. Guías de Accesibilidad (WCAG 2.1 AA) — Sin complejidad visual
  5. Responsive Design Sistemático — Breakpoints documentados
  6. Estados Interactivos Completos — Hover, focus, disabled, error
  7. Paleta Extendida Semántica — Neutral, Info, Success sin redundancia
  8. Guía de Implementación Frontend — HTML, CSS, JS patterns

① Tokens CSS + Sistema de Variables Documentado

MEJORA CLAVE

El sistema actual es visual. Esta mejora lo hace portable, escalable y consistente sin cambiar un solo píxel.

Problema actual

  • Colores, espacios y radios están definidos en archivos HTML individuales
  • No hay un "source of truth" único para los tokens
  • Duplicación de valores entre mockups, manual, y dossier
  • Integración con herramientas (Figma, Tailwind, StyledComponents) es manual

Solución propuesta

Paso 1: JSON de tokens centralizado

{ "color": { "primary": { "50": "#f0f7f5", "100": "#d9eae7", "500": "#0d4f4a", "600": "#0a3d39", "900": "#051f1c" }, "functional": { "critical": "#b3331f", "high": "#c2410c", "normal": "#a16207", "low": "#047857" } }, "space": { "xs": "4px", "sm": "8px", "md": "16px", "lg": "24px", "xl": "32px", "2xl": "48px", "3xl": "80px" }, "radius": { "sm": "6px", "md": "10px", "lg": "12px", "xl": "16px" }, "typography": { "fontFamily": { "sans": "'Outfit', system-ui, sans-serif", "mono": "'JetBrains Mono', monospace" }, "fontSize": { "xs": "11px", "sm": "13px", "base": "15px", "lg": "17px", "xl": "20px", "2xl": "28px", "3xl": "36px", "4xl": "40px" }, "lineHeight": { "tight": "1.2", "normal": "1.55", "relaxed": "1.65" } } }

Paso 2: CSS Custom Properties listos para usar

:root { /* Colors */ --color-primary-50: #f0f7f5; --color-primary-500: #0d4f4a; --color-functional-critical: #b3331f; /* Spacing */ --space-xs: 4px; --space-md: 16px; /* Typography */ --text-base: 15px; --leading-normal: 1.55; /* Derived tokens (composite) */ --btn-primary-padding: var(--space-sm) var(--space-md); --heading-1: 700 40px / 1.1 "Outfit"; }

Paso 3: Integración automática

  • Figma: Sync tokens automático vía Figma Tokens plugin
  • Tailwind: Generar config desde JSON
  • Storybook: Doc automática de valores
  • Código: Usar tokens en lugar de hardcoding colores
Impacto: Cambiar un color en un lugar = se actualiza en Figma, Tailwind, CSS y documentación automáticamente.

③ Sistema de Iconografía Minimalista

NUEVA

DeskWork carece de iconografía nativa. Propongo un set mínimo (30-50 iconos) diseñado para Help Desk.

Principios

  • Stroke-based (no solid fills) — simplicidad visual
  • Grid de 24x24 — escalable a cualquier tamaño
  • Peso de línea 2px — consistente con teal, no decorativo
  • Sin rellenos de color (usan herencia de `currentColor`)

Conjunto inicial propuesto

Categoría Iconos Uso en Help Desk
Estado de tickets circle-open, circle-process, circle-closed, circle-escalated Status badges en tablas, timeline
Acciones plus, minus, edit, trash, share, comment Botones de lista y cards
Navegación arrow-left, arrow-right, chevron-up, chevron-down, home, search Topbar y sidebar
Alertas alert-circle, info-circle, check-circle, x-circle Validación y mensajes
Help Desk específico headset, phone, clock, user, team, ticket Iconografía de dominio

Implementación

  • SVG inline o web font (IcoMoon)
  • Figma component para cada icono
  • Sizes: 16px, 20px, 24px (predefinidas)

④ Accesibilidad Documentada (WCAG 2.1 AA)

MEJORA CLAVE

Agregar una sección al manual de marca sobre accesibilidad sin cambiar el diseño.

Checklist de conformidad

Contraste de color (1.4.3 Contrast Minimum)

  • Texto normal: mín 4.5:1 ✓ (ink #14171e sobre bg #fafaf7 = 10.8:1)
  • Texto grande: mín 3:1 ✓
  • Componentes UI: mín 3:1 ✓ (botones, inputs, borders)

Tamaño de target (2.5.5 Target Size)

  • Mínimo 44x44px para elementos interactivos
  • Espaciado suficiente entre elementos táctiles (gap >= 8px)
  • Actualmente: botones 12px padding = ~40-44px, cumple

Estados focales (2.4.7 Focus Visible)

  • Outline en teal (--primary) de 2px
  • Offset 2px desde borde del elemento
  • Mantener en keyboard nav, visible en todos los states

Semántica HTML

  • Usar <button>, <input>, <label>, <select> apropiadamente
  • aria-label en iconos puros
  • aria-describedby para hints y errores
  • Roles landmarks: nav, main, aside, complementary

Tipografía

  • Tamaño mín 14px en body (actual cumple)
  • Line-height mín 1.5 para párrafos largos ✓
  • No usar text-align: justified (dificulta lectura)
  • Evitar mayúsculas sostenidas (ya está en anti-patrones)

⑤ Sistema Responsive Documentado

MEJORA FUNCIONAL

Actualmente el responsive es ad-hoc. Propongo breakpoints estándar y ejemplos claros.

Breakpoints propuestos

Nombre Ancho Uso
mobile 0px — 480px Teléfono, portrait
tablet 481px — 768px Tablet, landscape móvil
desktop 769px — 1024px Laptop pequeño
wide 1025px+ Pantallas grandes (4K, dual-monitor)

Estrategia mobile-first

/* Default: mobile 480px */ .grid { grid-template-columns: 1fr; } /* Tablet 768px */ @media (min-width: 769px) { .grid { grid-template-columns: repeat(2, 1fr); } } /* Desktop 1025px */ @media (min-width: 1025px) { .grid { grid-template-columns: repeat(3, 1fr); } }

Ajustes por breakpoint

  • Padding: 24px (mobile) → 36px (tablet) → 48px (desktop)
  • Tipografía: Sin cambios (legibilidad mín 14px en todos)
  • Componentes: Botones y inputs escalan con rem
  • Layout: Grid responsive + flexbox flexible

⑧ Guía de Implementación Frontend

MEJORA FUNCIONAL

Documento práctico para desarrolladores: "Cómo hacer HTML DeskWork sin romper la marca".

Contenido propuesto

1. Setup inicial

  • Copiar tokens.json y CSS custom properties
  • Importar tipografías (Outfit, JetBrains Mono)
  • Estructura HTML semántica base

2. Patrones comunes

  • Page layout (header, nav, main, footer)
  • Grid responsive (cómo usar grid-template-columns)
  • Flexbox utilities (gap, align, justify)
  • Composición de cards

3. Componentes reutilizables

  • Button (all variants + states)
  • Input (text, select, checkbox, radio)
  • Badge (status, priority, tag)
  • Card (content wrapper)
  • Modal (dialog pattern)
  • Toast (notification)

4. CSS Do's and Don'ts

  • ✓ Usar CSS variables (--primary, --space-md)
  • ✗ Hardcodear colores (#0d4f4a)
  • ✓ Usar gaps en lugar de margins
  • ✗ Margin mágico sin intención
  • ✓ Clases semánticas (.btn-primary)
  • ✗ Clases por apariencia (.blue-bold)
/* ✓ BIEN: Usar variables */ .btn-primary { padding: var(--space-sm) var(--space-md); border-radius: var(--radius-md); color: var(--primary); } /* ✗ MAL: Hardcodear */ .btn-primary { padding: 8px 16px; border-radius: 10px; color: #0d4f4a; }

5. Testing checklist

  • Keyboard navigation (Tab, Enter, Esc)
  • Screen reader (NVDA, JAWS, VoiceOver)
  • Mobile responsive (480px, 768px, 1025px)
  • Contrast verificado (WCAG AA)
  • Performance (sin animaciones pesadas)

Principios de la Propuesta

🎯 Mantener la simplicidad

Cada mejora suma capacidad sin complejidad visual. El sistema sigue siendo teal, minimalista, elegante.

📚 Documentación sobre código

No propongo componentes React. Propongo documentación clara y ejemplos HTML que cualquiera pueda seguir.

🔄 Retrocompatible

Las mejoras no rompen nada existente. El manual actual sigue válido. Los cambios son aditivos.

🛠️ Portátil

Tokens JSON = exportable a Figma, Tailwind, CSS, StyledComponents. No vendor lock-in.

♿ Accesible desde el inicio

WCAG 2.1 AA es parte de la especificación, no un agregado. Sin sacrificio visual.

🚀 Escalable

De 5 páginas del manual → 20 páginas de referencia. Del MVP Help Desk → SaaS completo.
