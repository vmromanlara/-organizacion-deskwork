Estructura Completa de Tokens

Archivo: design-tokens.json

Archivo único que es la fuente de verdad para todos los valores de diseño.

Ubicación recomendada

project/
├── tokens/
│ ├── design-tokens.json ← Fuente única
│ └── tokens.config.js ← Script de transformación
├── docs/
│ └── tokens-generated.md ← Docs auto-generadas
├── figma/
│ └── .figmatokens ← Sync con plugin Figma
└── src/
├── variables.css ← Generado desde tokens
└── tailwind.config.js ← Generado desde tokens

Cómo usar

  1. Guardar como design-tokens.json
  2. Crear script NodeJS que transforma a CSS variables, Tailwind config, etc.
  3. Sincronizar con Figma usando plugin "Tokens Studio"
  4. Versionear en Git para auditoría de cambios

Sistema de Responsive Grid

Breakpoints + Media Queries

Nombre Min-width Cambios principales
mobile 320px 1 columna, padding 16px
tablet 768px 2 columnas, padding 24px
desktop 1024px 3 columnas, padding 32px
wide 1400px 4 columnas, max-width container

Implementación CSS

/* Mobile first approach */

.page {
  max-width: 100%;
  padding: var(--space-md); /* 16px */
}

.grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--space-md);
}

.grid-2 { grid-template-columns: 1fr; }
.grid-3 { grid-template-columns: 1fr; }

/* Tablet */
@media (min-width: 768px) {
  .page {
    padding: var(--space-lg); /* 24px */
  }
  
  .grid-2 { grid-template-columns: repeat(2, 1fr); }
  .grid-3 { grid-template-columns: repeat(2, 1fr); }
}

/* Desktop */
@media (min-width: 1024px) {
  .page {
    max-width: 1000px;
    margin: 0 auto;
    padding: var(--space-xl); /* 32px */
  }
  
  .grid-2 { grid-template-columns: repeat(2, 1fr); }
  .grid-3 { grid-template-columns: repeat(3, 1fr); }
}

/* Wide */
@media (min-width: 1400px) {
  .page {
    max-width: 1200px;
  }
  
  .grid-4 { grid-template-columns: repeat(4, 1fr); }
}
Mobile-first: código base es mobile, media queries agregan características en screens más grandes. Resulta en CSS más eficiente.

Checklist de Accesibilidad WCAG 2.1 AA

Criterios implementados en DeskWork

Criterio WCAG Nivel Verificación en DeskWork Estado
1.4.3 Contrast (Minimum) AA Text: 4.5:1 mín | UI: 3:1 mín ✓ Cumple
1.4.11 Non-text Contrast AA Botones, bordes, iconos 3:1 ✓ Cumple
2.4.7 Focus Visible AA outline 2px en teal, offset 2px ✓ Cumple
2.5.5 Target Size AAA Mín 44x44px, gap 8px ✓ Cumple
2.4.3 Focus Order A Tab order lógico, sin tabindex positivo Requiere testing
1.3.1 Info and Relationships A Labels <label for>, ARIA describedby Requiere markup

Testing recomendado

  • Automated: axe DevTools, Lighthouse, WebAIM WAVE
  • Keyboard: Tab, Shift+Tab, Enter, Esc, Arrow keys
  • Screen reader: NVDA (Windows), VoiceOver (Mac/iOS), TalkBack (Android)
  • Visual: Color contrast checker (WebAIM)

Checklist de Implementación

Fase 1: Setup (1 semana)

  • ☐ Crear design-tokens.json con todos los valores
  • ☐ Generar variables.css automáticamente
  • ☐ Sincronizar con Figma (plugin Tokens Studio)
  • ☐ Documentar accesibilidad en manual
  • ☐ Crear archivo de breakpoints CSS

Fase 2: Componentes (2 semanas)

  • ☐ Especificar Input (text, email, number, textarea)
  • ☐ Especificar Button (primary, ghost, sizes)
  • ☐ Especificar validación y error states
  • ☐ Especificar loading spinners
  • ☐ Crear ejemplos HTML para cada uno

Fase 3: Iconografía (1 semana)

  • ☐ Diseñar 30-50 iconos en Figma
  • ☐ Exportar como SVG sprite
  • ☐ Crear clases CSS para tamaños
  • ☐ Documentar en manual

Fase 4: Documentación (1 semana)

  • ☐ Frontend implementation guide
  • ☐ Ejemplos interactivos en Storybook o similar
  • ☐ Testing checklist
  • ☐ Maintenance guide

Fase 5: Validación (1 semana)

  • ☐ Testing automatizado (Lighthouse, axe)
  • ☐ Testing manual con screen reader
  • ☐ Testing responsive (chrome devtools)
  • ☐ Feedback del equipo de desarrollo
